# Rubi Workshop 고객 포털 (portal.rubiworkshop.com)

루비워크샵 고객이 자기 빌드의 진행 단계, 결제, 견적, 구성, 사양을 보는 화면입니다. 직원용 포털 [my.rubiworkshop.com](https://my.rubiworkshop.com)(리포지토리 `sereno-kwon/my-rubi`)의 견적 앱에서 공개한 견적만 열립니다.

## 로그인 (고객코드)

- 고객은 **portal.rubiworkshop.com** 에 들어와 **고객코드**로 로그인합니다. 고객코드는 직원이 my.rubiworkshop.com 견적 앱(고객 포털 묶음)에서 고객마다 하나씩 발급하며 꼴은 `RUBI-가입연도-임의코드`입니다(예: `RUBI-2026-7K3M9QXP`).
  - 가입연도는 고객관리에서 그 고객(같은 이름)의 첫 건이 만들어진 해, 없으면 발급한 해입니다.
  - 임의코드는 숫자와 헷갈리지 않는 대문자 8자입니다(I·L·O·U 없음). 대소문자·하이픈·띄어쓰기는 상관없고, `RUBI` 를 빼고 연도부터 쳐도 됩니다. 임의 부분의 O는 0으로, I·L은 1로 읽습니다.
  - 임의 8자는 약 1조 가지라 추측할 수 없고, 틀린 코드가 10분에 30번을 넘으면 잠시 모든 코드 로그인을 막습니다.
  - 견적 앱의 **안내 문구 복사**로 포털 주소와 코드를 담은 문구를 카카오톡·문자에 붙여 보냅니다.
- **이 기기에서 로그인 유지**(기본 켬)면 다음부터 바로 목록이 열리고, 끄면 창을 닫을 때까지만 유지됩니다. 위 띠의 **로그아웃**으로 나갑니다.
- 코드가 새어 나갔으면 견적 앱에서 **다시 발급**합니다. 예전 코드는 바로 막히고, 이미 로그인한 기기와 예전 링크도 끊겨 로그인 화면으로 돌아옵니다.
- 견적 앱에서 고객이 몇 번 로그인했는지, 마지막으로 언제 했는지 보입니다.

## 첫 화면: 내 자전거

- 로그인하면 **'내 자전거' 목록**이 열립니다. my.rubiworkshop.com 첫 화면처럼 검은 바탕에 번호 목록(진행 중 · 견적 · 출고·루비케어)을 두고, 오른쪽에 Today(시각·쇼룸 시간), Payment(자전거별 결제 요청 금액과 입금 계좌), Rubi Care(보증 종료일), Contact(담당·전화)를 둡니다. ↑↓·Enter·숫자로 고르고 열며, 자전거가 4대 이상이면 `/` 찾기 칸이 생깁니다.
- 줄을 누르면 그 견적 상세(`#b/견적키`)가 열리고, 위의 **← 내 자전거**나 Esc로 목록에 돌아옵니다. 로그인으로 들어오면 주소에 고객 키가 남지 않습니다.
- 같은 고객 이름(띄어쓰기 무시, 고객관리에 연결된 견적은 고객관리 이름)으로 공개한 견적이 한 목록에 모입니다. 동명이인이면 고객관리에서 이름을 구분해 주세요(예: 홍길동 분당).
- 견적을 고친 뒤에는 **지금 내용으로 다시 공개**를 눌러야 고객 화면이 바뀝니다. **공개 끝내기**를 누르면 그 견적이 목록에서 바로 빠집니다. 진행 단계와 단계별 날짜는 고객관리에서 그때그때 읽어 오므로 단계만 바뀌었을 때는 다시 공개하지 않아도 됩니다.
- 직원용 **포털 미리보기** 링크(`#고객키`)와 예전에 보낸 견적 링크(`#견적키`)는 로그인 없이 열리고, 이 기기에 로그인 상태로 저장되지 않습니다.

## 보이는 것과 안 보이는 것

가격에 민감한 입력값은 정제한 사본만 공개합니다. 사본은 견적 앱이 만들고, Apps Script(`Code.gs` 의 `portalClean_`)가 허용한 칸만 다시 걸러 `포털` 탭에 저장합니다. 포털은 이 사본만 받습니다.

| 보임 | 안 보임 |
| --- | --- |
| 브랜드·모델·컬러, 고객명, 담당 | 줄별 소비자가·할인율·견적가 |
| 진행 단계 10단계와 단계별 날짜 | 줄 비고(업그레이드, 대외비 메모 등)·줄 시리얼 |
| 분류별 소비자가(프레임·구동계·휠셋·컴포넌트·옵션아이템·이큅먼트·서비스), 스페셜오퍼, 최종 견적 금액 | 전표처리, 이카운트 품목코드 |
| 결제 내역(결제 취소·환불은 괄호 음수), 결제 요청(단계·금액), 남은 금액, 입금 계좌(남은 금액이 있을 때만) | 내부 메모, 마일리지, 기록(날짜별 견적) |
| 구성품 이름(분류·세부항목, 증정·고객 지참 표시), 빌드 사양과 피팅 수치, S/N·F/N·루비 시리얼, 출고일·루비케어 보증 종료일, 비고 | 고객관리의 메모·기록 내용 |
| 떼어낸 부품(탈거품) 이름과 처리(고객 반환·매장 보관·보상 매입 등) | 탈거품의 시리얼·비고 |
| 업그레이드 견적 표시와 원래 견적 번호 | 원가·실질가·마진, 재고상태, 증빙(현금영수증·세금계산서) 번호와 발행 상태 |

## 화면

고객코드 로그인 → 첫 화면 '내 자전거' 목록 → 상세: 진행 단계(지금 단계와 설명) → 결제(결제 요청 금액, 입금 계좌, 결제 진행 막대, 결제 내역) → 견적(분류별 소비자가 막대, 스페셜오퍼, 최종 견적 금액) → 빌드 구성 → 떼어낸 부품(있을 때) → 빌드 사양 → 안내(비고) → 문의 전화. 휴대폰에서도 같은 순서로 보입니다.

출고한 자전거의 **업그레이드 견적**은 목록에 따로 한 줄로 나오고(부제에 '업그레이드'), 상세 위쪽에 '○○ 님의 업그레이드'와 원래 견적 번호가 보입니다. 새로 고친 판을 고객 화면에 보이려면 my-rubi 의 `Code.gs` 를 새 버전으로 배포한 뒤 견적 앱에서 **지금 내용으로 다시 공개**를 누릅니다(예전에 공개한 사본에는 새 칸이 없음).

## 파일

- `index.html` 화면 틀. 고객 전용 화면이라 검색에 나오지 않게 `noindex` 를 두었고 `robots.txt` 도 전부 막습니다(브랜드 사이트와 달리 검색 최적화를 하지 않는 페이지).
- `assets/portal.js` 불러오기와 그리기, `assets/portal.css` 모양(my.rubiworkshop.com 과 같은 서체 체계)
- `config.js` Apps Script 웹앱 주소(`API_URL`, my-rubi 의 `config.js` 와 같은 값), 매장 정보(주소·전화·운영시간·링크)
- `CNAME` portal.rubiworkshop.com

## 배포

1. 이 리포지토리 **Settings → Pages** 에서 `main` 브랜치 `/ (root)` 를 고르고 Custom domain에 `portal.rubiworkshop.com` 을 넣습니다(다른 브랜드 사이트처럼 Cloudflare Pages로 올려도 됩니다. 빌드 없이 루트 그대로).
2. rubiworkshop.com DNS에 `portal` CNAME 레코드를 GitHub Pages(`sereno-kwon.github.io`) 또는 Cloudflare Pages 주소로 추가합니다.
3. my-rubi 의 `Code.gs` 를 Apps Script 편집기에 붙여넣고 새 버전으로 배포해야 `portal` 동작과 견적 앱의 공개 버튼이 작동합니다.
